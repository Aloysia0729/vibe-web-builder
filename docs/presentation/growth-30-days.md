## Collect without inventing data

- Public repository counters provide Stars/Forks; save date, time, URL, and raw counts. Net change = current total minus Day 0 total, including losses.
- Authorized maintainers can inspect Insights → Traffic for views, unique visitors, clones, and referrers. Native data generally covers a rolling 14 days: save snapshots at each checkpoint, not only Day 30. Mark unavailable data N/A with the reason.
- Record window start/end for every traffic snapshot. Overlapping rolling windows must not be added together; avoid double-counting visitors. Do not claim per-link README clicks or installation conversions from repository traffic alone.
- Record real Issues, PRs, first contributions, and reproducible installation feedback. Do not count a page view as a successful user.
- At every checkpoint test language links, local images/GIF, documentation paths, and Quick Start with the supported host; record its exact version and untested alternatives.
- Log release announcements, community sharing, social posts, search/referral changes, and other concurrent events. No external database, tracking service, or paid tool is necessary.
