# 页面与交互规格

需求确认后按网站实际规模细化，不把模板扩成全功能清单。

## 页面表

每页分配 P01 等稳定 ID，记录用途、访问者、入口/导航、核心模块、操作、跳转、MVP/后续范围。复用合理路由；单页锚点可满足多类内容，不硬拆页面。用导航表或 Mermaid 表达关系，处理返回入口、断链和移动导航。

## 交互表

每项关键操作分配 I01 等 ID，关联页面及任务。明确元素、初始状态、触发、输入校验、系统响应、成功结果、异常处理、适用的加载/空/禁用状态及可观测验收。不适用写 N/A 和理由；静态链接无需虚构网络加载。

例：I02「保存笔记」位于 P02；未编辑时禁用；编辑后可提交；标题 trim 后 1–80 字；保存时禁止重复提交并显示状态；成功留在原页并显示“已保存”；失败保留输入可重试；未登录转登录页并保留返回地址。验收覆盖合法保存、空标题、失败、刷新后仍可读，以及实际需要账户隔离时的他人数据不可读。

## 完整性

- 每个 MVP 页面都在 sitemap，每个主要按钮/表单都对应交互和任务。
- 表单说明字段类型、必填、范围、错误位置和提交后行为；有服务端则也做服务端校验。
- 需长期数据时说明位置与权限；内存原型不能叫持久化完成。
- 移动端、易懂文案、语义、标签、焦点和键盘路径写进适用验收。
- 外部服务缺失列依赖/阻塞；可先用明确标注的本地模拟验证界面，不能声称服务已接通。
