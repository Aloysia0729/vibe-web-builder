# 验证与交付

复用已有测试与脚本，不为静态页面硬套 npm build。规划交付检查文档、规格和确认，不安装应用依赖。

| 检查 | 直接证据 |
|---|---|
| 安装/构建/类型 | 命令、目录、退出码和必要输出；零测试不是通过。 |
| 页面/路由 | 请求及预期内容；PID、开放端口或 HTTP 200 不能证明交互正确。 |
| 核心操作 | 按交互规格操作，核对跳转、状态、合法/非法输入、适用的失败恢复。 |
| 响应式 | 有浏览器时记录实测宽度（如 390/1280px）、溢出、导航和触控；无浏览器标未运行。 |
| 基础可访问性 | 键盘、焦点、标签、语义、对比度；扫描通过不等于全面合规。 |

缺能力可做代码阅读并记 inferred，不得冒充实测。不能虚构截图、远端状态、部署 URL、浏览器结果。宿主不提供预览时，不把内部 localhost 当公开链接。

## 有限修复

记录复现 → 判断原因 → 针对性修复 → 复测。默认同一问题最多三轮有依据的尝试，每轮改变诊断或条件；仍失败则保留结果、尝试、影响和下一步。不得关闭断言、伪造通过或把未验收任务标完成。继续安全的独立任务。

## 记录与交付

progress 每项记日期、命令/操作、目录、结果 passed/failed/not-run/inferred、证据、关联任务与限制。跳过、禁用、预期失败单独说明，不复用旧结果冒充当前运行。

交付说明真实完成页/功能、文件位置、前置条件、已验证本地运行命令、测试和问题。需要时提供 `.env.example`，只有变量名、用途和非秘密示例，用安全配置渠道填真实值。

按实际产物给静态托管或服务端部署步骤及适用的环境变量、迁移/回滚要点。指导不等于已部署；账号、密钥、资源、付费、生产、推送、部署先核对具体授权。最后保存恢复入口。
