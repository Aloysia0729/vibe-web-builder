# 分阶段开发

入口：development 模式、当前需求及草图分别确认、无阻塞问题。校验脚本只辅助核对版本，必须审查真实用户确认。planning 即使两门槛通过也不生成应用。

## 技术判断

先读代码、manifest、锁文件、AGENTS.md、CI、Git 改动与环境。沿用合理架构，保留用户成果。

依次判断：现有方案能否复用 → 静态页面是否足够 → 是否需复杂客户端交互 → 是否真需跨设备持久化/多人权限/服务端计算 → 是否必须第三方服务 → 开发维护成本。

展示信息和少量本地交互优先静态 HTML/CSS/JS 或现有生成器。复杂交互才用成熟框架；业务真需服务端和数据库才添加。不默认 React、数据库或特定部署商。用一两句说明适合网站的理由，仅在功能、费用或利益受影响时补问。

## 阶段

| 阶段 | 完成依据 |
|---|---|
| A 准备 | 代码目录、工具环境、MVP 页面/交互 ID、命令、验收明确；用户改动保留。 |
| B MVP | 核心页、导航和操作完成；实际启动并检查代表性请求/交互。 |
| C 扩展 | 按优先级补页面、数据和适用异常；无范围可省略或合并。 |
| D 验证 | 构建、核心操作、响应式、可访问性按能力验证，修复复测。 |
| E 交付 | 文件、真实运行命令、结果、限制、部署指导及下一步。 |

计划写 implementation-plan，结果写 progress。每阶段记录完成、未完成、测试、问题和下一步；验收有证据才完成。多个已授权低风险任务可连续执行，无需逐文件许可。

本地实现不授权推送、部署、付费或密钥操作。缺凭据先做独立任务，模拟须标明范围。失败时读输出、核对版本与锁文件、按诊断修复再复测，不关闭 TLS、签名或测试断言。无执行能力时标明未运行，不声称已验证。
